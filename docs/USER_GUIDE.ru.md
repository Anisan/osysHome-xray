# XRAY - Руководство пользователя

![XRAY Icon](../static/xray.png "Плагин XRAY")

## Назначение

`XRAY` это модуль системной диагностики для osysHome. Он дает администратору единую точку контроля для просмотра состояния рантайма и выполнения сервисных операций:

- фоновые циклы модулей;
- кэш;
- хранилище объектов в памяти;
- активность свойств и методов объектов;
- уведомления;
- состояние базы данных;
- пулы потоков и потоки;
- статистика cleaner;
- системное окружение Python и пакеты.

> [!IMPORTANT]
> В XRAY есть потенциально разрушительные действия (`clear`, `drop`, удаление из storage, очистка уведомлений). Используйте их только при понимании последствий.

## Что получает пользователь

| Возможность | Что делает |
| --- | --- |
| Управление сервисами | Запуск, остановка и перезапуск циклов модулей |
| Диагностика кэша | Просмотр ключей/значений и полная очистка |
| Диагностика storage | Статистика объектов в памяти и удаление записей |
| Телеметрия рантайма | Статистика чтения/записи свойств, вызовов методов, источники и время |
| Центр уведомлений | Отметка прочитанного/непрочитанного, удаление, массовая очистка |
| Диагностика БД | Информация о БД, размеры/строки таблиц, здоровье пула и история |
| Диагностика потоков | Метрики пулов, очередь, время задач, список потоков |
| Системная вкладка | Данные Python, список пакетов, установка пакета из UI |
| Аналитика | Графики в реальном времени по advanced-статистике объектов |
| Виджеты | `default` и `batch_writer` |

## Чек-лист быстрого запуска

- [ ] Откройте `/admin/xray`.
- [ ] Проверьте `Cycles` и убедитесь, что нужные модули работают.
- [ ] Проверьте `Database`: health score и загрузку пула.
- [ ] Проверьте `Thread Pools`: рост очереди, ошибки, отклоненные задачи.
- [ ] Проверьте `Notifications` и обработайте старые записи.
- [ ] Используйте очистку только при необходимости (`cache`, `storage`, `notifications`, таблицы).

## Частые пользовательские сценарии

### 1) Перезапуск зависшего циклического модуля

1. Откройте `Cycles`.
2. Найдите нужный модуль.
3. Нажмите `Restart` (или `Start`/`Stop`).

### 2) Очистка устаревшего кэша

1. Откройте `Cache`.
2. Просмотрите таблицу ключей/значений.
3. Нажмите `Clear cache`.

### 3) Удаление лишнего объекта из memory storage

1. Откройте `Objects storage`.
2. Найдите объект по имени/описанию.
3. Нажмите `Remove from storage`.

### 4) Работа с уведомлениями

1. Откройте `Notifications`.
2. Используйте действия в строке (`Read`, `Unread`, `Delete`).
3. Для массовых операций используйте `Read all` и `Clear all`.

### 5) Проверка здоровья БД и очистка таблиц

1. Откройте `Database`.
2. Проверьте метаданные БД и карточки пула.
3. Просмотрите размер и количество строк таблиц.
4. Используйте `Clear` или `Drop` только при полном понимании влияния.

> [!CAUTION]
> `Drop` удаляет саму таблицу, а не только данные.

### 6) Поиск узких мест по производительности

1. Откройте `Thread Pools` и проверьте утилизацию и последние задачи.
2. Откройте `Analytics` для топа методов, медленных методов, временной аналитики и уровней нагрузки.
3. Откройте `Methods` и `Properties` для детализации по объектам.

## Пояснения по вкладкам

### `Cycles`

- Показывает модули, у которых есть действие `cycle`.
- Отображает время последней активности и состояние alive/stopped.
- Доступны `Restart`, `Stop`, `Start`.

### `Cache`

- Показывает тип кэша (`redis`, `simple`, ...).
- Показывает срез ключей и значений в сортируемой таблице.
- `Clear cache` очищает весь кэш-бэкенд.

### `Objects storage`

- Показывает счетчики: `getObject`, `getProperty`, `setProperty`, `callMethod`.
- Доступна очистка всего storage и удаление отдельного объекта.

### `Properties`

- Показывает счетчики чтения/записи и временные метки.
- Показывает источник и текущее значение.
- Удобно для поиска шумных или устаревших свойств.

### `Methods`

- Показывает количество вызовов, последнее выполнение и суммарное время выполнения.
- Показывает источник вызова и параметры.

### `Notifications`

- Цветовая маркировка по категории.
- Поддержка read/unread, удаления одной записи, `Read all`, `Clear all`.

### `Database`

- Левая карточка: тип/версия/размер БД, счетчики и подключение.
- Правая часть: активные подключения, health score пула, overflow.
- График: история загрузки пула.
- Таблицы: количество строк/размер/модуль и admin-операции очистки.

### `Thread Pools`

- Обновление каждые 30 секунд.
- Метрики утилизации, очереди, completed/failed/rejected задач.
- Дополнительно метрики `batch_writer` и таблица последних задач.

### `Threads`

- Список всех потоков рантайма (`id`, `name`, `alive`, `daemon`).

### `Cleaner`

- История операций очистки по свойствам объектов и правилам хранения.

### `System`

- Информация о Python runtime, executable, venv, версии Flask.
- Список установленных пакетов (`pip list --format=freeze`).
- Установка пакета по имени через интерфейс.

### `Analytics`

- Графики в реальном времени (обновление каждые 30 секунд):
- распределение операций по объектам;
- топ методов по количеству вызовов;
- топ медленных методов;
- временная активность;
- распределение по уровням нагрузки;
- распределение источников;
- сводка health.

## Диагностика проблем

### Карточки пула не показывают данные

Проверьте:

- модуль XRAY корректно инициализировался;
- доступен API `/api/xray/database/pool/stats`;
- у пользователя есть права администратора и API key для вызовов API.

### Вкладка Thread Pools пустая

Проверьте:

- в рантайме доступны провайдеры метрик (`_poolLinkedProperty`, `_poolSay`, `_poolPlaysound`, `_batch_writer`);
- в консоли браузера нет ошибок по `/api/xray/thread_pools/stats`.

### Не устанавливается пакет на вкладке System

Проверьте:

- доступ сервера к интернету/репозиторию пакетов;
- права текущего python-процесса на `pip install`;
- корректность имени пакета.
